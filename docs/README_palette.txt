PALETTE SWAP: цвет шлема/костюма выбирает игрок, рисовать под каждый цвет не нужно
==================================================================================

КАК РИСОВАТЬ НОВЫЕ ДЕТАЛИ (шлемы, костюмы)
  Рисуй обычный серый шаблон, как Skin.png, и пользуйся ТОЛЬКО этими цветами
  (файл docs/skin_template_palette.gpl загружается в Aseprite: Palette > Load Palette):

    #8B93AF  основной         -> становится выбранным цветом
    #6D758D  тень             -> тень выбранного цвета
    #4A5462  глубокая тень    -> тёмный оттенок выбранного цвета
    #333941  подкладка        -> слегка тонируется выбранным цветом
    #122020  тёмная подкладка -> слегка тонируется
    #FFD541  акцент светлый   -> цвет АКЦЕНТА (визор, пояс, сапоги)
    #F9A31B  акцент тёмный    -> тень акцента
    #060608  контур           -> не меняется никогда

  Любые ДРУГИЕ цвета проходят без изменений (например, готовые Skin2..Skin5).
  Деталь автоматически считается «перекрашиваемой», если в ней есть пиксель #8B93AF.
  Никаких списков/флагов в коде поддерживать не нужно.

  В Aseprite держи режим RGB (не Indexed) и отключи сглаживание – цвета должны совпадать точно.
  Импорт в Godot: Filter = Nearest, Compress = Lossless (по умолчанию для 2D).

ПОЧЕМУ ЦВЕТ НЕ ТЕРЯЕТСЯ ПРИ СМЕНЕ СПРАЙТА
  Цвета лежат в материале на спрайте (PlayerSkin.colors), а не в картинке. Сменил текстуру
  шлема (head_inex / update_skin) – материал остался, и новый шлем сразу окрашен выбранным цветом.

МАСТЕРСКАЯ НА КОРАБЛЕ (смена цветов в игре)
  Твои кнопки «следующий/предыдущий шлем» работают как раньше. Для цветов добавь на тот же экран:

      var picker := SkinColorPicker.new()
      add_child(picker)
      picker.set_colors(player_skin.colors)
      picker.colors_changed.connect(func(c): player_skin.set_colors(c))
      # цвета сохранятся сами при следующем сохранении игры (SaveSystem.touch_slot_meta)

МУЛЬТИПЛЕЕР
  В загруженном коде нет apply_skin_rpc, поэтому цвета по сети я не подключал.
  Добавь к тому, что ты уже шлёшь (skin_index / head_inex), ещё  SkinColors.to_dict()
  (null вместо цветов = пустой словарь) и на приёме вызови
      skin.set_colors(SkinColors.from_dict(dict))
  from_dict безопасен: мусор или пустой словарь даёт null (оригинальные цвета), краша не будет.

ПРО СТАРЫЙ SkinPalleteChanger.gdshader
  Он нигде не подключён и работает по индексной схеме (номер цвета в канале R), для которой
  пришлось бы перерисовывать все спрайты. Я его не трогал и не использовал.
